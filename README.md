# 퀀트 에이전트 — 클라우드 버전

PC 없이 **GitHub Actions**가 파이프라인을 돌리고, **폰 웹앱**에서 버튼 하나로
실행·결과 확인·CSV 내려받기를 합니다. 한국장과 미국장을 따로 돌립니다.

```
              폰 (Streamlit)                    GitHub Actions
  ┌──────────────────────────────┐        ┌──────────────────────┐
  │ 🇰🇷 한국  /  🇺🇸 미국  전환    │        │ 일간 실행 (한국)      │
  │ ▶️ 일간 / 월간 실행 버튼      │ ─────▶ │ 월간 실행 (한국)      │
  │ 🔔 신호·상위 종목 확인        │ ◀───── │ 미국 일간 실행        │
  │ ⬇️ 결과 CSV 바로 내려받기     │        │ 미국 월간 실행        │
  └──────────────────────────────┘        └──────────────────────┘
                                             데이터: GitHub 릴리스
                                             (parquet, 약 150MB)
```

결과는 **사이트에서 CSV로 바로 받습니다.** 이메일 발송은 선택이고,
설정하지 않아도 전부 동작합니다.

## 두 시장

| | 한국장 | 미국장 |
|---|---|---|
| 종목 목록 | pykrx (KOSPI·KOSDAQ) | nasdaq.com 스크리너 API (NASDAQ·NYSE·AMEX, 약 6,000종목) |
| 섹터 | WISE 지수 | 스크리너의 Sector |
| 주가 | 네이버 금융 | yfinance (100종목씩 묶음) |
| 재무제표 | FnGuide | yahooquery (50종목씩 묶음) |
| 팩터 | QVM + MACD·RSI·볼린저 신호 | QVM만 (노트북과 동일) |
| 결과 | `model_kr_*.xlsx` | `model_us_*.xlsx` |

노트북에서 **손으로 하던 단계는 전부 자동화**했습니다. 미국 종목 목록은
nasdaq.com에서 CSV 3개를 직접 받아 읽었지만, 같은 화면이 쓰는 공개 API를
호출합니다. API가 막히면 `data/` 폴더의 `nasdaq_screener_NASDAQ.csv` 같은
파일로 대체합니다.

## PC 버전에서 바뀐 점

| 항목 | 이전 (PC) | 지금 (클라우드) |
|---|---|---|
| 데이터베이스 | 로컬 MySQL | `data/*.parquet` + DuckDB 조회 |
| 실행 | `run_daily.bat` 더블클릭 | GitHub Actions (자동 + 폰 버튼) |
| 데이터 보관 | PC 하드디스크 | GitHub 릴리스 `data-store` |
| 미국 종목 목록 | 스크리너 CSV 수동 다운로드 | nasdaq.com API 자동 호출 |
| 미국 주가 | 종목당 1회 요청 | 100종목 묶음 다운로드 |
| 미국 재무제표 | 종목당 1회 요청 | 50종목 묶음 호출 |
| 미국 배당수익률 | 종목당 yfinance (수 시간) | yahooquery 묶음 조회 (수 분) |
| 기술적 지표 | `pandas_ta` | `indicators.py` 자체 구현 |
| 주가 보관 | 5년 | 2년 (모델은 1년만 사용) |

`pandas_ta`는 관리가 끊겨 요즘 파이썬에 설치 자체가 되지 않습니다. 같은
정의(TA-Lib 기준)로 직접 구현했고, `tools/test_indicators.py`가 교과서 구현과
일치하는지 확인합니다. K_ratio는 statsmodels 결과와 1e-14 이내로 같습니다.

### 한국 모델도 글로벌 기준으로 통일했습니다

`factor-Global` 노트북에만 들어 있던 개선점을 `factor_core.py`로 모아 두 시장이
같은 정의를 쓰도록 했습니다. **한국 결과 숫자가 이전 노트북과 달라집니다.**

| 항목 | 이전 (한국) | 지금 (두 시장 공통) |
|---|---|---|
| 극단값 처리 | 상하위 1%를 버림(NaN) | 경계값으로 누름(winsorize) |
| 모멘텀 | 12개월 | 12개월 − 최근 1개월 (단기 반전 제거) |
| 무배당 종목 | DY 결측 → 밸류 팩터 전체 탈락 | DY를 0으로 보고 유지 |
| TTM | 4개 분기 단순 합 | 분기 간격이 400일 넘으면 무효 |
| K_ratio | 관측치 제한 없음 | 60개 미만이면 계산 안 함 |

가장 큰 차이는 첫 줄입니다. 예전에는 극단값을 버리면서 섹터가 작을수록 종목이
줄줄이 탈락해 **전체의 절반 가까이가 QVM 점수를 못 받았습니다.** 지금은 전 종목이
점수를 받습니다.

## 설치 (한 번만)

### 1. GitHub 레포 만들기

**Private 권장**. 코드에 비밀값은 없지만 모델 결과가 릴리스에 올라갑니다.

```bash
cd quant_cloud
git init && git add . && git commit -m "클라우드 퀀트 에이전트"
git branch -M main
git remote add origin https://github.com/<아이디>/<레포이름>.git
git push -u origin main
```

### 2. 레포 Secrets 등록

**Settings → Secrets and variables → Actions**

| 이름 | 값 | 없으면 |
|---|---|---|
| `KRX_ID` / `KRX_PW` | data.krx.co.kr 계정 | pykrx가 비로그인으로 동작 — 티커 수집이 빈 데이터면 이게 원인 |
| `ANTHROPIC_API_KEY` | Claude 진단 리포트용 | 기본 텍스트 리포트로 대체 |
| `QUANT_SMTP_USER` / `QUANT_SMTP_PASS` / `QUANT_REPORT_EMAIL` | Gmail 주소 / 앱 비밀번호 16자리 / 받을 주소 | 메일만 안 감 |
| `QUANT_TG_TOKEN` / `QUANT_TG_CHAT_ID` | 텔레그램 봇 | 텔레그램만 안 감 |

**하나도 없어도 됩니다.** 결과는 사이트에서 보고 CSV로 받으면 되고,
실행이 **실패**하면 GitHub가 레포 주인에게 알아서 메일을 보냅니다.

### 3. 먼저 테스트 실행 (중요)

**Actions → 월간 실행 → Run workflow** → `ticker_limit`에 **30** → 실행.
미국장도 같은 방식으로 **미국 월간 실행**을 30종목으로 한 번.

3~5분 뒤 초록불이 뜨면 해외 IP에서 수집이 된다는 뜻입니다. 전체 실행은
몇 시간이라 실패하면 오래 기다린 게 날아갑니다. 두 시장 다 먼저 확인하세요.

### 4. 전체 월간 실행

`ticker_limit`을 **0**으로 두고 한국·미국 각각 한 번씩. 재무제표까지 채워져야
일간 실행이 동작합니다. 0단계에서 MySQL 데이터를 올렸다면 이미 채워져 있습니다.

### 5. 폰 화면 배포 (Streamlit)

1. <https://share.streamlit.io> → GitHub 로그인 → **New app**
2. 레포 선택 → Main file `app.py` → Deploy
3. **Settings → Secrets**:

```toml
APP_PASSWORD = "원하는_비밀번호"
GH_TOKEN = "github_pat_..."
GH_REPO = "아이디/레포이름"
```

> **GH_TOKEN**: GitHub → Settings → Developer settings → Personal access tokens →
> **Fine-grained tokens** → 이 레포만 선택 → **Actions: Read and write**,
> **Contents: Read-only**. 만료일은 1년으로 넉넉히.
>
> `export_from_mysql.bat`으로 릴리스에 직접 올릴 때는 **Contents: Read and write**가
> 필요합니다(파일을 쓰기 때문). 대시보드용 토큰은 읽기만 있으면 됩니다.

4. 폰 브라우저로 열고 **홈 화면에 추가**.

## 쓰는 법

화면 맨 위에서 **🇰🇷 한국 / 🇺🇸 미국**을 고르면 아래가 전부 그 시장으로 바뀝니다.

| 탭 | 하는 일 |
|---|---|
| 🔔 매수 신호 / 상위 종목 | 한국은 매매 신호, 미국은 QVM 상위 100 · CSV 내려받기 |
| ▶️ 실행 | 그 시장의 일간/월간 버튼, 진행 상태 |
| 📊 모델 | 섹터 필터, 팩터 분포, 걸러본 화면 그대로 CSV |
| 📜 기록 | 실행 리포트, 단계별 로그, 전체 이력 |

### 자동 실행

| 워크플로 | 시각 (한국) | 내용 |
|---|---|---|
| 일간 실행 | 평일 16:30 | 한국 주가 갱신 + QVM + 매매 신호 |
| 월간 실행 | 매월 1일 09:00 | + 2년 주가 + FnGuide 재무제표 |
| 미국 일간 실행 | 평일 06:30 | 미국장 마감 뒤 주가 갱신 + QVM |
| 미국 월간 실행 | 매월 2일 21:00 | + 2년 주가 + yahooquery 재무제표 |

한국과 미국은 서로 막지 않습니다(실행 그룹이 분리돼 있음). 한쪽이 실패해도
다른 쪽은 그대로 돕니다.

### CSV 내려받기

받기 전에 용도를 고르세요.

| 고른 것 | 종목코드 | 언제 |
|---|---|---|
| 엑셀에서 열기 | `="005930"` 로 텍스트 고정 | 엑셀·구글시트 (기본) |
| pandas로 읽기 | `005930` 그대로 | 코드로 읽을 때 |

엑셀은 CSV의 `005930`을 숫자 `5930`으로 바꿉니다. 한국 종목코드에선 치명적이라
기본값을 엑셀 안전 모드로 뒀습니다. pandas로 읽을 땐 `dtype={"종목코드": str}`를
주세요. 파일은 UTF-8 BOM이라 한글이 깨지지 않습니다. (미국 심볼은 문자라 무관합니다.)

## 무료 한도

Private 레포 기준 월 **2,000분**입니다. 네 워크플로를 다 돌리면:

| | 1회 | 월 합계 |
|---|---|---|
| 일간 (한국) | 약 30분 × 22회 | 660분 |
| 월간 (한국) | 약 3시간 | 180분 |
| 미국 일간 | 약 25분 × 22회 | 550분 |
| 미국 월간 | 약 1.5시간 | 90분 |
| | | **약 1,480분** |

한도의 3/4쯤이라 여유가 많지는 않습니다. 모자라면 둘 중 하나:

- `.github/workflows/us-daily.yml`의 `cron`을 `30 21 * * 1,3,5`로 (주 3회) → 약 220분 절약
- 레포를 **Public**으로 전환 → Actions 분 무제한 (대신 모델 결과가 공개됩니다)

## 문제 해결

**한국: 티커 수집이 빈 데이터를 반환한다**
`KRX_ID` / `KRX_PW` Secrets를 등록하세요. pykrx는 계정이 있으면 로그인해서
가져오고, 없으면 비로그인으로 시도합니다.

**한국: 수집 실패율이 높다**
해외 IP 차단일 가능성이 큽니다. 실행 버튼의 **고급 설정**에서 동시 요청 수를
`2`로 낮춰 보세요.

**미국: 주가가 통째로 안 들어온다**
Yahoo가 GitHub 서버 IP를 제한한 것입니다. **고급 설정**에서 yfinance 묶음 크기를
`30`까지 낮추면 대개 통과합니다. `curl_cffi`로 브라우저를 흉내 내고 있지만
Yahoo의 제한은 시기에 따라 오르내립니다.

**미국: 종목 목록을 못 받는다**
nasdaq.com API가 막힌 경우입니다. nasdaq.com 스크리너에서 CSV를 받아
`data/nasdaq_screener_NASDAQ.csv` (NYSE, AMEX도 같은 식)로 넣고 커밋하면
그 파일로 대체합니다.

**"kor_fs / global_fs가 비어 있습니다"**
그 시장의 월간 실행을 아직 완주하지 않았습니다. 월간이 한 번 끝나야 일간이 돕니다.

**엑셀에서 종목코드 앞의 0이 사라졌다**
CSV 받을 때 **엑셀에서 열기**를 고르세요.

**어느 날부터 자동 실행이 멈췄다**
GitHub는 레포에 60일간 커밋이 없으면 스케줄을 끕니다. Actions 탭 안내에서
다시 켜거나 가끔 커밋을 올리세요.
